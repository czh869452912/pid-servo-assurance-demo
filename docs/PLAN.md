# 研发与保证计划（演示裁剪版）

## 1 工程约定

配置项 CSCI-PID-SERVO，运行环境是主机 C11 单元测试程序，输出为归一化伺服控制量。输入来自虚构的台架上层控制器 SYS-DEMO-001；不连接实机作动器。

过程：计划 → 需求 → 设计 → 编码 → 需求验证 → 评审 → 基线。阶段转换通过 `.factory/project.json` 的受控变更与人工评审记录，插件只呈现来源信息。当前处于验证阶段，不自动认定此前评审已经通过。

角色：开发者提交代码与测试；审核者审查候选诊断成果；配置/质量责任人处置正式 PR、问题和基线。专业智能体提供候选，不能自行批准正式评审。本例同一 GitHub 账号创建 PR，因此正式独立批准状态保持待评审。

演示产物：SRS、SDD、SVP、配置与质量说明、八项需求 Issue、追溯矩阵、提交 SHA、Actions 日志与 JUnit、故障 PR。配置索引是固定提交下的 Git 树及 CI 产物；本例不建立正式发布基线。

GJB 438C 关注开发文档内容与关系，DO-178C 关注按软件等级确定的过程目标与生命周期数据。未给定系统安全评估时，本例不指定 DAL。GJB 5000B 原文尚未获取，不对其条款作符合性映射。

范围外工作保留为空缺项：计划批准、独立性证明、需求完整性/正确性正式评审、目标机与时序测量、结构覆盖分析、工具鉴定、质量审核、配置审计、符合性汇总与认证联络。

## 2 扩充工程范围

算法SU-PID与监督SU-SERVO共12条需求、12项测试：8单元、3模块集成、1配置项台架仿真。9类工程文档、六要素用例、保证配置与精确输入快照补充过程证据。四条监督需求是台架衍生候选，尚未人工批准；云端旧工程八需求单独版本，不自动回写。
