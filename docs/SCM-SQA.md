# 配置管理与质量记录约定

受控项：SRS、SDD、SVP、过程定义、追溯矩阵、接口、实现、测试、CI 工作流。每次变更由 Git commit SHA 标识；CI 证据记录对应 SHA、run ID、attempt、结论。Issue 正文有独立 updated_at/内容哈希，不能与 Git 文档版本混同。

需求 Issue 使用 `requirement` 标签与 REQ-PID 编号。需求变更应同步 SRS、设计分配、测试和矩阵，经 PR 评审后形成新的受控版本。GitHub Issue 编辑与提交不是原子事务，演示不声称已实现正式需求基线冻结。

PR 必须引用受影响需求，说明变更、验证与未解决问题。由独立审核者在指定 head SHA 提交 reviews；旧提交上的批准不得自动视为新 head 已批准。CI 是执行证据，review 是人工决定，两者独立显示。

演示平台的“接受 AI 诊断成果”只批准候选进入个人处理，不批准 GitHub PR、关闭问题或发布。正式发布还需要计划/需求/设计评审、完整验证、问题处置、质量审查与配置审计。本例不创建“已认证”标签。

当前记录：需求/设计为演示初稿，CI 可提供主机证据；正式独立评审、质量审核与发布基线尚未完成。流程状态与来源断线时，插件应显示未知/获取失败及观察时间，而不能沿用旧数据显示成功。
